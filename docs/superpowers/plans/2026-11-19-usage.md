# Usage Implementation Plan

> **For agentic workers:** work task by task, in order. Each task is test first: write the tests named in the task, see them fail, write the code, see them pass, commit. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** blimpd counts token usage from Claude Code's and Codex's session files, prices it, keeps the Claude limit numbers from the status line, and the Mac app shows it in a bottom bar and a Usage window.

**Architecture:** A child process (`blimpd usage-scan`) reads only new bytes of each session file and adds hourly totals to a SQLite file (`bun:sqlite`, no new dependency). blimpd answers `GET /usage` and `GET /usage/now` from that file and from small limit files that `blimpd statusline` writes. The app only draws what the server sends.

**Tech stack:** Bun 1.4.3 (`~/.bun/bin/bun`; it is not on PATH in a plain shell), TypeScript, `bun:sqlite`, `bun test`. App: React 19, Vite, no chart library.

**Spec:** `docs/superpowers/specs/2026-11-19-usage-design.md`. Read it first. Where this plan and the spec differ, the spec wins; say so in your report.

## Shared types (exact names; later tasks rely on them)

```ts
// src/usage/prices.ts
export type Counts = { replies: number; input: number; output: number; cacheRead: number; write5m: number; write1h: number };
export type Tier = "" | "fast" | "long";
export type Price = { input: number; output: number; cacheRead: number; write5m: number; write1h: number }; // USD per million tokens
export type Entry = Price & { fast?: number; long?: { over: number; price: Price } }; // fast: a multiplier; long.over: prompt tokens

// src/usage/summary.ts (the app copies these two into app/src/lib/usage.ts)
export type Sum = { replies: number; input: number; output: number; cacheRead: number; cacheWrite: number; cost: number; helperCost: number };
export type UsageView = {
  scanning: boolean;
  firstDay?: string; // "2026-10-16", the first local day with a reply
  totals: Sum;
  days: { day: string; byAccount: Record<string, number>; byModel: Record<string, number> }[]; // cost, every day of the range, oldest first
  accounts: (Sum & { id: string; email?: string })[]; // most cost first
  models: (Sum & { model: string; priced: boolean })[];
  projects: (Sum & { project: string })[]; // 20, then { project: "" } for everything else when there is more
  unpriced: string[];
  note?: string; // why prices.json was ignored
};
export type Window = { used: number; resetsAt: number; reset: boolean }; // used 0 to 100; resetsAt ms
export type NowView = {
  accounts: { id: string; email?: string; inUse: boolean; at?: number; fiveHour?: Window; sevenDay?: Window }[];
  codex?: { at: number; plan?: string; windows: (Window & { minutes: number })[] };
  today: { cost: number; tokens: number };
  statusline: boolean;
};
```

Account ids in rows: a Claude account's `accountUuid`; `""` (a Claude reply nobody can be named for); `"other"` (a model that does not start with `claude-`); `"codex"`.

### Task 3: The scan

**Files:** Create `src/usage/scan.ts`, `test/usage-scan.test.ts`. Modify `src/main.ts` (add `usage-scan`).

**Consumes:** Task 1 (`entryFor`, `modelKey`, `readPrices`), Task 2 (`openUsage`, `readTimeline`, `accountAt`).

**Produces:**
```ts
export type ScanDirs = { usage?: string; claude?: string; codex?: string; accounts?: string; record?: string; prices?: string };
export function scan(dirs?: ScanDirs, now?: number): { files: number; replies: number }; // files read, replies added
export function runUsageScan(): number; // `blimpd usage-scan`: scan(), prints nothing, 0 (1 and the error on stderr if it throws)
```
Defaults: `claude` is `claudeDir()`, `codex` is `process.env.CODEX_HOME || ~/.codex`, `accounts` is `accountsDir()`, `record` is `recordFile()` (both from `src/accounts/store.ts`).

Rules (spec, "Counting"):

1. Walk every `*.jsonl` under `<claude>/projects` and `<codex>/sessions` (recursive). For each, compare its size with `files.at`: equal, skip; smaller, skip; larger, read from `at`.
2. Read in chunks of 8 MB with `openSync`/`readSync`; never hold a whole file. Work on full lines only: the bytes after the last `\n` are not counted and `at` stops before them. Parse a line only if it contains `"usage"` (Claude) or `"token_count"`, `"turn_context"` or `"session_meta"` (Codex); check that on the bytes before decoding, because first runs read 13 GB.
3. One transaction per file (`db.transaction`): the row additions, the `seen` keys, and the new `files.at` (and `extra`) together.
4. A Claude line counts when `type === "assistant"`, `message.usage` is an object, `message.model` is a string other than `"<synthetic>"`, and `timestamp` parses. Key: `` `${message.id}:${requestId ?? ""}` ``; `insert or ignore into seen`, and count the reply only when a row was inserted. `seen.day` is `Math.floor(ms / 86_400_000)`.
5. Counts from `message.usage`: `input = input_tokens`, `output = output_tokens`, `cacheRead = cache_read_input_tokens`, `write1h = cache_creation?.ephemeral_1h_input_tokens ?? 0`, `write5m = max(0, cache_creation_input_tokens − write1h)`; a missing number is 0.
6. Row key: `hour = Math.floor(ms / 3_600_000)`; `model` as written; `project = cwd ?? ""`; `helper = isSidechain === true || the path has "/subagents/"`; `tier = "fast"` when `usage.speed === "fast"`, else `"long"` when `entryFor(model, extra)?.long` and `input + cacheRead + write5m + write1h > long.over`, else `""`.
7. Account: model does not start with `claude-` → `"other"`. Else with a timeline → `accountAt(timeline, ms)`. Else (no log) → the `accountUuid` in the record file (`readRecord(record)?.id`), or `""`.
8. Add with one statement: `insert into rows values (…) on conflict (hour, account, model, project, helper, tier) do update set replies = replies + excluded.replies, …`.
9. A Codex file keeps `extra = JSON.stringify({ model, cwd, input, cached, output })`. `session_meta` and `turn_context` set `cwd` (`payload.cwd`) and, on `turn_context`, `model` (`payload.model`). An `event_msg` whose `payload.type === "token_count"` and has `payload.info.total_token_usage`: the growth of `input_tokens`, `cached_input_tokens`, `output_tokens` since the kept totals. When any grew: one reply, `input = grown input − grown cached`, `cacheRead = grown cached`, `output = grown output`, account `"codex"`, the kept model (`""` if none yet), helper 0, tier `""`, hour from the line's `timestamp`. A total smaller than the kept one counts nothing; the kept totals become the new ones either way. If the line has `payload.rate_limits` and its `timestamp` is newer than `meta.codexLimit`'s `at`, store `meta.codexLimit = JSON.stringify({ at: <ms>, plan: rate_limits.plan_type, primary: rate_limits.primary, secondary: rate_limits.secondary })`.
10. After the walk: delete `files` rows whose path is gone from disk; `delete from seen where day < today − 40`; set `meta.scanEnded = String(now)`.

Fixtures are written by small helpers in the test (a Claude line builder and a Codex line builder), not checked-in files.

`summarize`:
- `db` undefined, or no `meta.scanEnded`: `{ scanning: true, totals: all zero, days: [], accounts: [], models: [], projects: [], unpriced: [] }`.
- Local day of an hour: `Math.floor((hour * 3_600_000 + tz * 60_000) / 86_400_000)`, written `YYYY-MM-DD`. The range is the last `days` local days, today included; it never starts before `firstDay`. `days` has every day of it, also days with nothing.
- Cost per row is `costOf(row, model, tier, extra)`; `undefined` adds 0 and puts the model in `unpriced`. `cacheWrite = write5m + write1h`. `helperCost` is the cost of rows with `helper = 1`.
- `accounts` carry `email` from `emails`. `models` group by the model as written; `priced` is whether a price was found. `projects`: the 20 with the most cost, then one `{ project: "" }` with the rest when there are more. Each list most cost first, then most tokens.

`nowView`:
- `accounts`: the saved accounts in order, `inUse` for `active`, each with `limits[id]`. With none saved: the record's account with `limits["one"]` and `inUse: true`; with no record either, an empty list.
- A window is `{ used, resetsAt, reset: resetsAt <= now }`.
- `codex`: from `meta.codexLimit`: `windows` from `primary` and `secondary` where present, `minutes = window_minutes`, `used = used_percent`, `resetsAt = resets_at * 1000`.
- `today`: cost and tokens (input + output + cacheRead + cacheWrite) of today's local day.

`service.ts`: the child is `Bun.spawn([...selfCommand(), "usage-scan"], { stdin: "ignore", stdout: "ignore", stderr: "ignore" })`; a module variable holds it while it runs and the time it ended. Use `setTimeout`/`setInterval` with `.unref()` if other timers in `server.ts` do; follow what is there.

Routes (in `route`, style as the lines around them; bad parameters are `HttpError(400, …)`):
- `GET /usage?days=&tz=`: `days` an integer 1 to 3660, default 30; `tz` an integer −840 to 840, default 0. Calls `ensureScan()`, opens the database read only, answers `summarize(…)`, closes it. `emails` from `listSaved()` and `readRecord()`.
- `GET /usage/now?tz=`: `nowView(…)`. It does not start a scan.
