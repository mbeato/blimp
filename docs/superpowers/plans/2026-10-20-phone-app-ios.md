# Phone app, part 2: the iPhone app, with voice — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native iPhone app that lists every blimp session by project, opens one as a chat, sends messages, answers Claude's questions with buttons or by voice, reads replies aloud, and starts, stops and ends sessions, talking to blimpd's existing API.

**Architecture:** Everything that's logic lives in `ios/BlimpKit`, a Swift package with only Foundation, so it's tested with `swift test` on Linux and macOS (CI). The app target `ios/Blimp` (SwiftUI, iOS 26) holds the screens, networking (`URLSession` HTTP + WebSockets), Keychain, Face ID, and voice (SpeechAnalyzer, AVSpeechSynthesizer). The Xcode project is generated from `ios/project.yml` by XcodeGen. A new workflow `.github/workflows/ios.yml` builds and tests on every push that touches `ios/`.

**Tech Stack:** Swift 6, SwiftUI, Swift Testing, XcodeGen, iOS 26 SDK (Xcode 26), GitHub Actions (`ubuntu-latest`, `macos-latest`).

**Spec:** `docs/superpowers/specs/2026-10-19-phone-app-design.md` (sections 3, 4, Errors, Tests). blimpd's API as built: `docs/DESIGN.md` (blimpd API, Events, Chat).

## Global Constraints

- iOS 26 minimum. Bundle id `dev.blimp.phone`. Display name "blimp". No third-party Swift packages.
- `BlimpKit` imports only Foundation (it must build and test on Linux). Nothing UI, Speech, AVFoundation or Security in it.
- The app never stores the token anywhere but the Keychain (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, service `dev.blimp.phone`, account `server`).
- Plain HTTP only to `127.0.0.1` and `localhost` (development through an SSH forward). Everything else is HTTPS.
- Assistant text is rendered natively (SwiftUI `Text` with `AttributedString`), never in a web view, and never as HTML.
- Links open only on tap, `http`/`https` only, in Safari.
- Speech recognition runs on the device; no audio leaves the phone.
- Voice never sends an answer it isn't sure of: a `guess` is highlighted and waits for a tap.
- Look: system light/dark, system font, the amber accent only for "waiting".
- Copy in the UI is plain English, short.
- Commits: no `Co-Authored-By` or any Claude attribution.
- Branch `phone-chat` only. Push with `git push origin phone-chat`; never push to `main`, never force-push. To pick up `main`, merge it in (`git merge origin/main`), don't rebase.

## How to build and check (every task)

There is no Swift toolchain on claude1. The checks run on GitHub:

1. Commit, then `git push origin phone-chat`.
2. `gh run list -R mbeato/blimp -w iOS -b phone-chat -L 1` to get the run id, then `gh run watch <id> -R mbeato/blimp --exit-status` (run it in the background if your tool allows, and wait for it to finish; don't poll in a tight loop).
3. On failure: `gh run view <id> -R mbeato/blimp --log-failed | tail -100`, fix, commit, push, repeat. Five tries at most per task, then report BLOCKED with the last error.
4. A task is done only when both jobs (`kit-linux`, `app`) are green for its last commit.

Apple API details you're not sure of (SpeechAnalyzer, SpeechTranscriber, AssetInventory, AVSpeechSynthesizer, LocalAuthentication, URLSessionWebSocketTask): read Apple's docs (`https://developer.apple.com/documentation/speech/speechanalyzer` etc., via WebFetch) before writing the call, and let the compiler settle the rest.

```swift
// ios/BlimpKit/Sources/BlimpKit/Models.swift
// blimpd's API types (docs/DESIGN.md). Decoding is lenient: a state or kind this app doesn't
// know yet decodes as unknown/other instead of failing the whole list.
import Foundation

public enum SessionState: String, Codable, Sendable, Equatable {
    case working, waiting, done, unknown
    public init(from decoder: Decoder) throws {
        self = SessionState(rawValue: try decoder.singleValueContainer().decode(String.self)) ?? .unknown
    }
}

public enum PromptKind: String, Codable, Sendable, Equatable {
    case permission, question, other
    public init(from decoder: Decoder) throws {
        self = PromptKind(rawValue: try decoder.singleValueContainer().decode(String.self)) ?? .other
    }
}

public struct QuestionOption: Codable, Sendable, Equatable {
    public let label: String
    public let description: String?
}

public struct Question: Codable, Sendable, Equatable {
    public let question: String
    public let header: String?
    public let multiSelect: Bool
    public let options: [QuestionOption]
}

public struct Prompt: Codable, Sendable, Equatable {
    public let kind: PromptKind
    public let at: Double
    public let answerable: Bool
    public let tool: String?
    public let summary: String?
    public let options: [String]?
    public let questions: [Question]?

    /// What the buttons say, in order; the index is what `answer` sends as `pick`.
    public var choices: [String] {
        switch kind {
        case .permission: options ?? []
        case .question: questions?.first?.options.map(\.label) ?? []
        case .other: []
        }
    }
}

public struct Session: Codable, Sendable, Equatable, Identifiable {
    public let name: String
    public let created: Double
    public let dir: String
    public let kind: String
    public let label: String?
    public let sessionId: String?
    public let title: String
    public let updatedAt: Double?
    public let state: SessionState
    public let stateSince: Double?
    public let prompt: Prompt?

    public var id: String { name }
    /// blimpd can show a session as chat only when Claude Code runs in it.
    public var isClaude: Bool { sessionId != nil }
    /// Milliseconds: the latest thing that happened in it.
    public var activity: Double { max(updatedAt ?? 0, stateSince ?? 0, created * 1000) }
}

public enum ChatRole: String, Codable, Sendable, Equatable {
    case user, assistant, tool
    public init(from decoder: Decoder) throws {
        self = ChatRole(rawValue: try decoder.singleValueContainer().decode(String.self)) ?? .tool
    }
}

public struct ChatMessage: Codable, Sendable, Equatable, Identifiable {
    public let id: String
    public let at: Double
    public let role: ChatRole
    public let text: String?
    public let name: String?
    public let summary: String?
    public let input: String?
    public let output: String?
    public let error: Bool?
}

public enum ChatEvent: Sendable, Equatable {
    case history([ChatMessage]), append([ChatMessage]), reset, unreadable
    case ack(id: String), failed(id: String, error: String), other

    private struct Wire: Decodable { let type: String; let messages: [ChatMessage]?; let id: String?; let error: String? }

    public static func decode(_ data: Data) -> ChatEvent {
        guard let w = try? JSONDecoder().decode(Wire.self, from: data) else { return .other }
        switch w.type {
        case "history": return .history(w.messages ?? [])
        case "append": return .append(w.messages ?? [])
        case "reset": return .reset
        case "unreadable": return .unreadable
        case "ack": return w.id.map { .ack(id: $0) } ?? .other
        case "error": return .failed(id: w.id ?? "", error: w.error ?? "")
        default: return .other
        }
    }
}

public enum EventsMessage: Sendable, Equatable {
    case sessions([Session]), other

    private struct Wire: Decodable { let type: String; let sessions: [Session]? }

    public static func decode(_ data: Data) -> EventsMessage {
        guard let w = try? JSONDecoder().decode(Wire.self, from: data), w.type == "sessions", let s = w.sessions else { return .other }
        return .sessions(s)
    }
}

public enum ChatCommand: Encodable, Sendable, Equatable {
    case input(id: String, text: String)
    case answer(id: String, at: Double, pick: Int)
    case interrupt(id: String)

    private enum Key: String, CodingKey { case type, id, text, at, pick }

    public func encode(to encoder: Encoder) throws {
        var c = encoder.container(keyedBy: Key.self)
        switch self {
        case let .input(id, text):
            try c.encode("input", forKey: .type); try c.encode(id, forKey: .id); try c.encode(text, forKey: .text)
        case let .answer(id, at, pick):
            try c.encode("answer", forKey: .type); try c.encode(id, forKey: .id); try c.encode(at, forKey: .at); try c.encode(pick, forKey: .pick)
        case let .interrupt(id):
            try c.encode("interrupt", forKey: .type); try c.encode(id, forKey: .id)
        }
    }
}

public struct RecentFolder: Codable, Sendable, Equatable { public let dir: String; public let lastUsed: Double }
public struct Conversation: Codable, Sendable, Equatable, Identifiable {
    public let sessionId: String; public let title: String; public let updatedAt: Double
    public var id: String { sessionId }
}
public struct Started: Codable, Sendable, Equatable { public let name: String }
public struct Health: Codable, Sendable, Equatable { public let version: String; public let home: String }
```

Note: `at` in `encodesCommandsExactly` encodes `5` from a `Double` of 5. On Linux and macOS, `JSONEncoder` writes `5` for 5.0 (it writes integral doubles without a fraction). If CI shows `5.0` on either, change the test's expected strings to match what both produce and say so in the report; blimpd compares `at` numerically, so both are fine on the wire.

### Task 2: BlimpKit logic — chat log, home, pairing, backoff, Markdown

**Files:**
- Create: `ios/BlimpKit/Sources/BlimpKit/{ChatLog,Home,PairLink,Backoff,Markdown}.swift`
- Test: `ios/BlimpKit/Tests/BlimpKitTests/{ChatLog,Home,PairLink,Backoff,Markdown}Tests.swift`

**Interfaces:**
- Consumes: Task 1's types.
- Produces:
  - `struct ChatLog: Equatable, Sendable` — `messages: [ChatMessage]` (read-only), `readable: Bool`, `mutating func apply(_ e: ChatEvent)`: `history` replaces messages and sets `readable = true`; `append` replaces by `id` or adds at the end; `reset` empties messages; `unreadable` sets `readable = false`; others change nothing.
  - `struct ProjectGroup: Equatable, Identifiable, Sendable` — `dir` (= `id`), `name` (last path component, or the whole dir for `/`), `sessions: [Session]` (newest `created` first), `waiting: Bool`, `activity: Double` (max of its sessions').
  - `struct HomeList: Equatable, Sendable` — `waiting: [Session]` (state `.waiting`, oldest `stateSince` first), `projects: [ProjectGroup]` (most recent `activity` first; ties by `name`); `static func make(_ sessions: [Session]) -> HomeList`.
  - `struct ServerLink: Codable, Equatable, Sendable` — `url: URL, token: String`; `static func parse(_ text: String) -> ServerLink?`: accepts `blimp://pair?url=<encoded>&token=<t>` (surrounding whitespace trimmed); `url` must be `https` with a host, or `http` with host `127.0.0.1` or `localhost`; token must match `^[0-9a-f]{64}$`; the url keeps no trailing `/`.
  - `enum Backoff { static func delay(attempt: Int) -> Double }` — 1, 2, 5, 10, then 10 (seconds; attempt 0 → 1).
  - `enum MarkdownBlock: Equatable, Sendable` — `paragraph(String)`, `heading(level: Int, text: String)`, `bullets([String])`, `numbered([String])`, `code(language: String, text: String)`, `quote(String)`, `table(String)`, `rule`; `static func parse(_ text: String) -> [MarkdownBlock]` (rules below).

Markdown rules (Claude's replies are GitHub-flavoured Markdown; this is enough to show them well, not a full parser):
- A line starting with ```` ``` ```` opens a code block (the rest of the line, trimmed, is the language); it ends at the next line starting with ```` ``` ```` or at the end of the text. Inside, nothing else is parsed.
- `#`…`######` then a space: heading.
- Consecutive lines starting with `- `, `* ` or `+ `: one `bullets` (each item's text after the marker; a line indented by 2+ spaces that isn't a marker continues the previous item, joined with a space).
- Consecutive lines starting with `<digits>. `: one `numbered`.
- Consecutive lines starting with `>`: one `quote` (marker and one following space removed, lines joined with `\n`).
- Consecutive lines starting with `|`: one `table` (raw lines joined with `\n`; shown in monospace).
- A line that is only `---`, `***` or `___`: `rule`.
- Other consecutive non-blank lines: one `paragraph`, joined with `\n`. Blank lines separate blocks.
- Inline marks (`**bold**`, `` `code` ``, links) stay in the strings; the app renders them with `AttributedString(markdown:options: .inlineOnlyPreservingWhitespace)`.

SpokenText rules (spec section 4):
- Code blocks and tables → "code skipped." (one per block). Inline code longer than 40 characters → "code skipped"; shorter inline code → its text without backticks.
- Links `[text](url)` → `text`; bare `http(s)://…` URLs → "link".
- Paths with more than three parts (a token with 3+ `/` separators, like `src/app/lib/x.ts` or `/home/u/a/b`) → the last part (`x.ts`, `b`).
- Markdown marks removed: `#` headings, `**`, `__`, `*`/`_` emphasis around words, `>` quotes, list markers (`- `, `* `, `1. `).
- Each block ends with a sentence break: blocks are joined with " " after making sure each ends in `.`, `!`, `?` or `:` (add `.` if not).
- Whitespace collapsed to single spaces; result trimmed.

`Prompt.spoken`:
- permission: "Claude wants to " + (summary with its leading "Ran " → "run ", "Edited " → "edit ", "Wrote " → "write ", "Read " → "read ", "Searched for " → "search for ", backticks removed, through `SpokenText`) + ". " + choices joined as "A, B, or C?" (with only two: "A or B?"). Long choices are cut at the first comma ("Yes, and don't ask again for …" → "Yes, and don't ask again" is fine: cut at the second comma; simpler rule: cut each choice to its first 6 words).
- question: for each question: its text, then its options in the same "A, B, or C?" form.
- other: "Claude is asking something. Open it on the Mac."

VoiceAnswer rules (never guess silently):
1. Normalise: lowercase, `'` removed, other punctuation → space, collapse spaces.
2. Numbers: a heard number 1–9 as a digit, a word (`one`…`nine`) or an ordinal (`first`…`ninth`), alone or after `option`/`number`/`the`, or followed by `one` ("the second one") → `.clear(n-1)` if in range, else `.none`.
3. Label: if the heard text equals a normalised choice, or is a prefix of exactly one normalised choice and has 2+ words, or exactly one normalised choice is contained in the heard text → `.clear(i)`.
4. Yes/no alone (the heard text is one of `yes, yeah, yep, sure, ok, okay, allow, do it, go ahead` / `no, nope, dont, deny, stop, cancel`): the first choice whose normalised label is exactly `yes` or starts with `yes ` → `.clear`; for no, the last choice whose normalised label is exactly `no` or starts with `no ` → `.clear`. No such choice → `.none`.
5. Otherwise, word overlap: for each choice, the share of its words (ignoring `the, a, an, and, for, to, of, in`) that were heard. The best choice with share ≥ 0.6 and strictly ahead of the second best → `.guess(i)`. Else `.none`.
